# Контекст проекта: приложение «Обходчик» (`qr_scan_industry`)

Источник правды по этому Flutter-приложению. Всё выведено из кода, конфигов и
git-истории репозитория `sampo_smart_mobile`, а не из общих практик Flutter.

Android-приложение для обходчика на производстве: сканирует QR оборудования,
закрывает задачи ТО и осмотра, фиксирует проблемы и наработку, ведёт ремонты,
смотрит остатки ЗИП, получает уведомления. Работает офлайн — всё пишется в Hive
и уходит очередью. Только русский, только портрет, только светлая тема,
единственная роль — `walker`.

## Правила принятия решений

- **Исполняемый код — первичный источник правды.** Документация авторитетна,
  пока совпадает с кодом.
- **Навигация делится на два вида.** Вглубь — `push` (предыдущий экран
  остаётся, «назад» вернёт сам). Сброс — `clearStackAndNavigate` (вход, выход,
  онбординг). Кнопка «назад» — всегда `backOr(fallback)`.
- **Есть локальные данные — рисуй их сразу**, а сеть пусть обновляет уже
  показанное. Не держи экран на спиннере до ответа сервера.
- **Фильтруй на сервере, а не на телефоне**, если у эндпоинта есть фильтр.
- **Токены приоритетнее хардкода**: `AppConstants.spacingMD`, а не `16`;
  `cs.primary`, а не `Colors.green`.
- **Готовые компоненты приоритетнее ручной сборки.** Пустой список — это
  `EmptyState`, а не собранный на месте `Column`.
- **Устаревшее не сохраняем вслепую.** `theme_extensions.dart`, семейство
  `select_*_button` — мёртвые. Не расширяй их.
- **Никогда не выдумывай поведение продукта.** Нет в коде — значит неизвестно.
  Спрашивай или помечай как unknown.
- `design/README.md` — боилерплейт генератора тем, к проекту отношения не имеет.

## Пять фактов, которые ломают работу, если их не знать

1. **Hive без кодогенерации.** Каждый `TypeAdapter` написан руками: `read()`
   читает поля **строго в том порядке**, в котором их пишет `write()`. Смена
   порядка или типа ломает данные на устройствах. Единственный безопасный приём
   — дописать поле **в конец** `write()` и прочитать через `try/catch`
   (образцы: `scan.dart`, `repair.dart`). `typeId` переиспользованию не подлежат.

2. **`.env` в корне обязателен и читается дважды** — `flutter_dotenv` в Dart и
   `java.util.Properties` в Gradle **на этапе конфигурации**. Gradle там же
   создаёт `signingConfigs.release`, поэтому без валидного keystore падает даже
   debug-сборка. Значения — без кавычек. Файл едет внутрь APK через assets.

3. **Линтера фактически нет.** `analysis_options.yaml` подключает отсутствующий
   пакет, набор `linter.rules` не применяется. «Так делает анализатор» — не
   аргумент; ориентируйся на форму соседнего кода. Эталон — **1 предупреждение**.

4. **`flutter test` красный.** Единственный тестовый файл закомментирован,
   `main()` в нём нет. Тестов в проекте нет вообще — не отчитывайся об их
   успешном прогоне.

5. **Методы из `extension` видны только там, где импортирована библиотека
   целиком** (`api.dart`, `data_provider.dart`), а не part-файл. Забыть этот
   импорт — типовая ошибка проекта.

## Рецепты

### Новый экран

1. Виджет в подпапку по фиче: `lib/src/<фича>/<имя>_screen.dart`.
2. `GoRoute` в `MyApp._router`: `pageBuilder`, возвращающий `NoTransitionPage`
   — анимации переходов в приложении нет.
3. **Ветка в `MyAppBar.build`** — иначе экран получит дефолтный тёмный AppBar с
   одной кнопкой «Выйти». Исключение: заголовок зависит от данных (номер
   ремонта, пилюля статуса) — тогда экран строит свой `AppBar`.
4. Маршрут по умолчанию защищённый; публичный — добавить в
   `isGoingToProtectedRoute` в `redirect`.
5. Переход вглубь — `push`, кнопка «назад» — `backOr('/запасной_путь')`.

### Новый эндпоинт или справочник

1. Метод — extension в существующем part-файле `http/*_api.dart` (новый домен →
   новый part + строка `part` в `api.dart`). Шаблон — `code-conventions.md`.
2. Модель в `model/` с `fromJson`.
3. Нужен офлайн — рукописный `TypeAdapter` (новый `typeId`, следующий свободный
   **29**) → регистрация в `main.dart` → открытие бокса → поле в конструкторе
   `DataProvider`. Одиночное значение или флаг клади в `stringBox`.
4. `sync<X>()` по образцу `syncUsageUnitTypes` + вызов в `mainSync()`.
   **Крупный справочник в `mainSync` не добавляй** — так поступили с каталогом
   ЗИП, см. `data-and-integrations.md`.
5. Данные держатся в памяти — обнови кэш `DataProvider` после записи.

### Новая отправляемая сущность (офлайн-очередь)

Общее: модель с `key()`, `add<X>()` в `DataProvider`, `sync<X>()` в
`data_provider_outbox.dart`, вызов в цикле `startScanSyncing`, учёт в
отладочной полосе. Дальше — по признаку побочного эффекта:

- **нет** (осмотр, наработка, ad-hoc задача) → пара боксов `<x>` + `pending_<x>`,
  возврат из pending через 120 с. Образец `syncPeriodicTasks`;
- **есть** (ремонт: сервер меняет состояние оборудования и шлёт уведомления) →
  один бокс и `Idempotency-Key` вместо таймаута. Образец `syncPendingRepairs`.
  Ключ считается один раз при создании; многошаговая отправка фиксирует
  прогресс в боксе после каждого шага; отказ сервера отличается от отсутствия
  связи и от протухшего токена; отклонённое не повторяется автоматически.

### Правка UI

Цвета — `cs.*` и `AppSemanticColors`; отступы и радиусы — `AppConstants.*`.
Ничего, что уже задано под-темой (`Card`, `TextField`, `AppBar`, `SnackBar`),
локально не переопределяй. Пустой список — `EmptyState`, нижний лист —
`showAppModalSheet`, подтверждение — `Dialogs.areYouSure`.

### Рефакторинг

Прочитай `REFACTORING_CHECKLIST.md` — там записано, что сделано и что
**осознанно отложено**. Не начинай переезд папок (Phase 8) попутно. Не трогай
`read`/`write` Hive-адаптеров.
