# Глоссарий

Русское слово, идентификатор в коде и то, чем оно **не** является.

## Продукт

**Обходчик** (`walker`) — единственный тип пользователя приложения. Не путать с
администратором: тот работает в веб-админке `sampo_smart_frontend` и в
приложение не пускается.

**Sampo Smart / ТОиР / enterprise54** — одна и та же система: бэкенд
`sampo_smart_backend`, веб-админка `sampo_smart_frontend`, приложение
`sampo_smart_mobile`.

**Обход** — рабочий цикл: прийти к оборудованию → отсканировать QR → закрыть
задачи, зафиксировать проблему, внести наработку → отправить.

**Компания** (`Company`) — арендатор системы. Приложение читает её ради тарифа
и фича-флага `allowRequestsWithoutQr`.

## Домен

**Оборудование / ТМЦ** (`InventoryRecord`, в API — `equipment`). **Разнобой
имён:** класс `InventoryRecord`, бокс `inventory`, эндпоинт
`/v1/company/equipment`, метод `getEquipment()`, переменная в UI часто
`machine`. Это всё одно и то же.

**Осмотр** (`Scan`, в API — `fault_inspection`) — то, что обходчик отправляет по
итогам обхода. Класс называется `Scan`, но семантически это **осмотр**, а не
результат сканирования QR.

**Задача** (`Task`) — единица работы по оборудованию. `resultStatus`: `open`
(назначена человеку), `scheduled` (по периодичности, адресована **роли**),
`closed`.

**Периодическая задача** (`PeriodicTask`) — правило повторения, живёт внутри
`Task.periodicTask`. **`PeriodicTaskRequest` — не то же самое:** это тело
запроса на создание, которое приложение кладёт в очередь (ad-hoc задачи по
проблеме «Другое»).

**ТО** — техническое обслуживание. Распознаётся **по подстроке в русском
названии**: `periodicTitle.contains('Техническое обслуживание')`. Такие задачи
получают метку в `stringBox` и не отправляются, пока не уйдёт наработка по тому
же оборудованию.

**Типовая проблема** (`TypicalProblem`, в API — `eq_fault`). Два псевдоэлемента:
`TypicalProblem.empty` (id −1, «Нет проблем») и `TypicalProblem.other` (id 0,
«Другое» — требует комментария **и** приоритета, порождает ad-hoc задачу).

**Наработка** (`UsageParameter` — параметр, `UsageUpdate` — обновление) —
показание счётчика: моточасы, километры, циклы. Обходчик видит только параметры,
чей `maintenanceRole.name` совпадает с его `effectiveRole`.

**Состояние оборудования** (`EquipmentState`) — словарь `код → русское название`.
Меняется **сразу**, не через очередь. Исключение — «В ремонте»: его ставит
сервер при создании ремонта.

**Ремонт** (`Repair`) — «Открыт» → «На рассмотрении» → «Закрыт». Обходчик
доводит до «На рассмотрении»; закрывает и списывает склад **администратор**. Не
путать с `Task`: задача — единица обхода, ремонт — отдельная сущность со
складскими последствиями.

**ЗИП** (`SparePart`) — запасные части, инструменты и принадлежности. В
приложении справочник только для чтения.

**Фактический расход** (`RepairConsumption`, в API — `actual_consumptions`) —
сколько ЗИП израсходовано. Заполняет обходчик, но **списание происходит не в
момент ввода**, а при закрытии ремонта администратором. Пустой список =
списания не будет.

**Норма расхода** (`ConsumptionNorm`) — плановый состав ЗИП по оборудованию.
Справочный ориентир: сама по себе ничего не списывает.

**Расход ЗИП по задаче** (`SparePartUsage`, в API — блок `spare_part_usage`) —
план (`planned`) и факт (`actual`) по периодической задаче. `mode`: `norm` —
план из нормы расхода, `manual` — из состава задачи, `null` — расход по задаче
не настраивали (план пуст, но факт указать можно). **Не путать с
`RepairConsumption`:** тот у ремонта, этот у задачи осмотра, и списывается он
сервером в момент приёма осмотра, а не при закрытии ремонта.

**Нехватка на складе** (`InsufficientStockException`, `shortages`) — сервер
ответил 409 с `detail_code: insufficient_stock` и списком «нужно / есть».
Осмотр помечается отклонённым и ждёт обходчика на экране разрешения конфликта.

**ППР** (`Ppr`) — планово-предупредительный ремонт: набор периодических задач со
своим сроком. Статусы сервера `QUEUED` («В очереди») и `IN_PROGRESS`
(«В работе»). Не путать с `Repair`: ППР — это план работ по многим единицам
оборудования, ремонт — отдельная сущность со складскими последствиями. Раздел
живёт за флагом `PPR_ENABLED` (`FeatureFlags.pprEnabled`).

**Черновик ремонта** (`PendingRepair`) — ремонт, созданный без связи. Серверного
номера нет, в списке помечается «Черновик». Его `localId` — одновременно ключ
бокса и `Idempotency-Key`.

**Ответственный и должность** — у ремонта может быть исполнитель
(`responsible_user`), должность (`responsible_role`) или оба. Должность без
исполнителя = **свободный** ремонт: виден каждому обходчику подходящей роли,
можно «взять в работу».

**Роль исполнителя** (`CustomRole` / `customRoleId` / `MaintenanceRole`) — две
разные системы сопоставления: задачи по `id` (`customRoleId` ↔
`periodicTask.customRoles[].id`), наработка по имени (`effectiveRole` ↔
`maintenanceRole.name`). Не перепутай.

**Инвентаризация** (`Session`) — сессия пересчёта. Полноценного UI в приложении
**нет**, экран удалён; видна только в отладочной строке.

**Приоритет** (`Priority`) — `low` / `medium` / `high`. Цвета в самой модели
захардкожены; для UI бери `AppSemanticColors` (`cs.priorityLow/Medium/High`).

## Технические термины

**`GlobalState`** — статический класс-хаб: `dataProvider`, текущий пользователь,
время в UTC, отладочная строка, кэшированная проверка связи.

**`DataProvider`** — единственный «репозиторий»: боксы, in-memory кэш,
синхронизация, очереди. Разбит на part-файлы `_remote`, `_sync`, `_outbox`.

**`Settings`** — статические пользовательские настройки поверх `stringBox`. Не
путать с `NotificationSettings` — это модель серверных настроек уведомлений.

**Outbox / очередь** — две схемы: пара боксов `<X>` + `<X>Pending` с возвратом
через 120 с (осмотры, наработки, задачи) и один бокс с `Idempotency-Key`
(ремонты).

**`key()`** — md5 от JSON-содержимого, ключ элемента очереди → дедупликация по
содержимому.

**`stringBox`** — бокс `strings` типа `Box<String>`: настройки, флаги
онбординга, timestamp-ы очереди, метки ТО. Для одиночных значений; коллекции
живут в типизированных боксах.

**`typeId`** — номер Hive-адаптера. Занято 0–4 и 6–29, следующий свободный 30;
`5` освобождён, но переиспользованию не подлежит.

**`Idempotency-Key`** — заголовок, по которому сервер узнаёт повторную отправку
и возвращает уже созданную сущность вместо второй. На нём держится офлайн-очередь
ремонтов.

**`simulateOffline`** — статический рубильник `API.simulateOffline`: `isAlive()`
возвращает `false`, остальные методы бросают `SocketException`.

**`hasConnectionToServer`** — геттер `GlobalState`, который **не** проверяет
состояние сети: он пингует сервер (`GET /docs`, таймаут 5 с) и кэширует ответ на
10 секунд.

**Окно недоступности** (`API.isServerKnownUnreachable`, `offlineWindow` 30 с) —
отметка «сервер только что не отозвался»: пока она стоит, `_client` отказывает
мгновенно, не открывая соединение. Не то же самое, что `hasConnectionToServer`:
тот отвечает на «идти ли вообще», эта — «идти сейчас бесполезно».

**`mainSync()`** — синхронизация оперативных справочников, десять штук
параллельно; каталог ЗИП снова в их числе (он инкрементальный). Не путать с
`syncScans()` (отправка очереди) и `syncDataAndScans()` (кнопка
«Синхронизировать данные»).

**`ensureSparePartsLoaded()`** — подтягивает каталог ЗИП, если его ещё нет.
Вызывают экраны, которым он нужен сразу.

**`backOr(fallback)`** — `pop()` на предыдущий экран, а если стек пуст — сброс
на запасной адрес. Стандартный способ реализовать кнопку «назад».

**`clearStackAndNavigate(path)`** — `pop()` до дна + `pushReplacement`. Только
для сбросов: вход, выход, splash, онбординг.

**`MyAppBar`** — не виджет, а класс со **статическим** методом
`build(BuildContext)`, возвращающим `AppBar` по текущему маршруту.

**`AnyController<T>`** — обобщённая обёртка над `ValueNotifier<T?>` для значений
формы.

**`ControllerListenerMixin`** — миксин на `State`, подписывающий на один
`Listenable` с автоматической отпиской.

**`AppThemeId`** — `fresh` (лаймовый зелёный, дефолт) и `industrial` (графит).

**`AppSemanticColors`** — extension на `ColorScheme` с ролями `success`,
`warning`, `info`, `priority*`.

**`Dependent<T>`** — обёртка над `ValueListenableProvider` + `Consumer`. Один
потребитель; для нового кода — штатный `ValueListenableBuilder`.

**Демо-оборудование** (`DemoEquipment`, uuid `demo-onboarding-conveyor`) —
специально распознаётся в `getTasksForMachine` и `QRResultScreen`. Не сломай
демо-ветку.

**Отладочная полоса** — постоянная строка внизу каждого экрана: связь,
неотправленные осмотры, пользователь. Часть продукта, а не временная отладка.

## Легко перепутать

| Пара | Разница |
|---|---|
| `Scan` ↔ сканирование QR | `Scan` — **осмотр**, отправляемая запись |
| `SparePartUsage` ↔ `RepairConsumption` | Расход по задаче осмотра ↔ расход по ремонту; списываются в разные моменты |
| ППР ↔ ремонт | План работ по многим единицам ↔ одна сущность со складскими последствиями |
| Окно недоступности ↔ `hasConnectionToServer` | Мгновенный отказ на 30 с ↔ пинг сервера с кэшем на 10 с |
| `ServerFailureException` ↔ `SocketException` | Сервер ответил и отказал ↔ запрос не доехал |
| `Task` ↔ `Repair` | Задача — единица обхода; ремонт — сущность со складскими последствиями |
| `Repair` ↔ `PendingRepair` | Известен серверу ↔ черновик в очереди |
| `PeriodicTask` ↔ `PeriodicTaskRequest` | Данные с сервера ↔ тело запроса на создание |
| Норма расхода ↔ фактический расход | План ↔ факт; списывается факт |
| Закрыть ремонт ↔ отправить на рассмотрение | Закрывает только администратор |
| `responsible_user` ↔ `responsible_role` | Исполнитель ↔ должность; должность без исполнителя = свободный ремонт |
| «Отправить» (ремонт) ↔ отправка очереди | Перевод статуса ↔ выгрузка накопленного |
| `customRoleId` (int) ↔ `effectiveRole` (String) | Задачи по `id`, наработка по имени |
| `NotificationSettings` ↔ `Settings` | Серверные настройки уведомлений ↔ локальные настройки |
| `NotificationsService` ↔ `PushNotificationsController` | Список и SSE в main-изоляте ↔ управление foreground-сервисом |
| `notification_router.dart` ↔ `go_router` | Обработка тапа по пушу, не маршрутизация |
| `skip` ↔ `offset` | В URL всегда `skip`, в сигнатуре метода — `offset` |
| `design/README.md` ↔ документация | Боилерплейт генератора тем, к проекту отношения не имеет |
