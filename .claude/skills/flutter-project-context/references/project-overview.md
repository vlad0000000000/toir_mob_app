# Обзор продукта

## Назначение

Мобильное приложение **«Обходчик»** — клиентская часть системы ТОиР
**Sampo Smart**. Пользователь — рабочий на производстве, который физически
обходит оборудование: сканирует QR, видит паспорт и назначенные задачи,
закрывает осмотры, фиксирует неисправности, вносит показания счётчиков, меняет
состояние оборудования, ведёт ремонты и смотрит остатки ЗИП.

## Ограничения, заложенные в код

- **Офлайн-устойчивость.** Всё, что вводит обходчик, сначала ложится в Hive и
  только потом уходит очередью с ретраями. Потеря связи не должна терять данные.
- **Только роль `walker`** — любая другая получает `WalkerOnlyException`.
- **Только русский.** `flutter_localizations` не подключён и подключить его
  нельзя (конфликт версий intl ломает сборку).
- **Только портрет, только светлая тема.**
- **Работа в перчатках при плохом освещении** — крупные тап-таргеты и высокий
  контраст.

## Пользователь один

**Обходчик** (`walker`). Разграничения по экранам внутри приложения нет;
`effectiveRole` и `customRoleId` используются только для фильтрации:

- задача `scheduled` видна, если `periodicTask.customRoles` содержит
  `customRoleId` пользователя;
- задача `open` — если совпадает `responsibleUser.uuid`;
- параметр наработки — если `maintenanceRole.name` совпадает с `effectiveRole`.

## Платформы

**Считать проект Android-only.** `Dockerfile` собирает только APK, весь
push/foreground-код за `Platform.isAndroid`. Каркас iOS есть, но не
сопровождается (в `ios/` лежат чужие Firebase-конфиги). Web — деградированный
режим.

## Точки входа

`lib/main.dart` → `main()`: логирование, push-контроллер, портретная ориентация,
`dotenv`, путь Hive через `HiveStorageLocation.resolve`, регистрация **28**
адаптеров, открытие **20** боксов, сборка `DataProvider`, возврат зависших
`pending_scans`, публикация статиков, восстановление темы, запуск фоновых
циклов, `runApp`.

Вторая точка входа — `notificationsForegroundCallback` в
`notifications/push/notifications_task_handler.dart` (`@pragma('vm:entry-point')`),
изолят foreground-сервиса.

## Главные фичи

1. **Вход** — JWT, офлайн-фолбэк на локально сохранённых пользователей.
2. **Онбординг** — 4 видео + демо-оборудование.
3. **Сканирование QR** и **экран результата** — ядро продукта: паспорт, задачи,
   проблема, приоритет, фото, наработка, смена состояния.
4. **Список оборудования и задач.**
5. **Ремонты** — создание из карточки скана и работа по назначенным; фактический
   расход ЗИП, фото, отправка на рассмотрение. Полностью работает офлайн через
   очередь с идемпотентностью и разрешением конфликтов. Закрытие и списание —
   у администратора.
6. **Справочник ЗИП** — поиск, фильтры, карточка с историей движения.
7. **Центр уведомлений** + **push** через Android foreground-service с
   собственным SSE (без FCM).
8. **База знаний** — WebView.
9. **Сервис** — ручная синхронизация, сброс осмотров, диагностика, настройки.

Детально — `features-and-flows.md`.

## Ключевые проектные ограничения

- **Формат Hive нельзя менять «на месте»** — см. SKILL.md, факт 1.
- **Одиночные значения — в `stringBox`**, коллекции — в типизированных боксах.
- **Цвета и отступы — только из дизайн-системы**, новых констант не заводить.
- **Строки — в `lib/strings.dart`**, класс на фичу.
- **`flutter analyze` должен оставаться на 1 предупреждении.**
- **Публичные пути API менять нельзя** — контракт держит бэкенд.
- **Закрытие ремонта и списание ЗИП в приложении не реализуются.**
